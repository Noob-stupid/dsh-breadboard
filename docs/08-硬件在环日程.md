## 0. 目标，以及"怎么算成功"

**目标（用户明确）**：**这是个插件，最终目的是「基本上所有硬件都能适配通用」。**
让插件从「虚拟硬件」走到「**真硬件在环**」，并把这套**适配能力做成通用的**。

★★ **验收判据 —— 把"通用"拆成可度量的三级**（这就是用户要验的那件事）：

| 级别 | 接一块**全新**板子要做什么 | 说明 |
|---|---|---|
| **L1 数据级** ⭐理想 | **只加一条型号定义**（引脚表：`portId` ↔ 丝印、电压、方向）—— **零代码** | 能立刻摆、能按真实丝印连线、能查电压/方向/上拉错误 |
| **L2 适配器级** ✅合格 | **只新增一个适配器文件**（探测工具链 / 烧录 / 回读），**不动核心** | 能烧录与回读 ⇒ 真机在环 |
| **L3 改核心** ❌不通过 | 被迫改装配层 / 校验层 / 工具表 / 面板 | **抽象失败** ⇒ 回头重做 P4 |

- 达到 **L2** ⇒ 「**硬件适配是通用的**」这句成立（**P5 用 STM32 验的就是这一条**）；
- 若 STM32 只能走 **L3** ⇒ 那时候的"能搞"只是"**又硬编了一块板子**"。

⇒ **这就是把 STM32 排在最后的原因：它是验收，不是目标。** 拿它当第一块板做，
   会把"针对 STM32 的硬编"误当成"通用能力"。

★ **为什么"所有硬件"要靠生态而不是靠我们**：我们不可能自己适配所有硬件 ——
所以真正可行的形态是 **适配器可以由第三方提供**（一个适配器包 / 一份型号定义），
插件提供**开放接口 + 注册机制**。**这就是这个插件做"通用"的现实路径**：
我们定接口与流程，生态往里填硬件。

## 0.1 与早先 ABC 的对应关系（同一套能力，重新分组）

用户问过「是根据之前提的 ABC 兼容路线吗」—— **是**。ABC 不是被推翻，而是被**重新分组**：

| 早先 | 含义 | 在终版里落到 |
|---|---|---|
| **A** | 调用工具链（生成 / 编译 / **烧录** / 复位）| **P3**（ESP32 烧录）；STM32 的那份 A ⇒ **P6** |
| **B** | 固件本身在仿真里跑（Renode / QEMU）| **P5 —— 保留在主线**（与真机线并列，不互相阻塞）|
| **C** | 真机在环（虚拟装配 ↔ 真板）| **拆成两条**：**P1**（服务端回读）+ **P2**（串口回读）|

**两处实质变化**（都不是换路线，而是补上缺口）：

1. **新增 P4「适配器抽象」** —— 这是终版最重要的一条。
   没有它，P1–P3 只是"**又硬编了一块板子**"；有了它，P6（STM32）才能当**验收**。
   ⇒ 你问的"到时候硬件驱动是不是基本都能搞"，**判据就落在 P4**（见 §0）。
2. **顺序按"要件是否齐备"而非字母** —— ESP32 三要件齐（板/工程/工具链），
   STM32 三要件全无 ⇒ **ESP32 先行、STM32 收尾**。

**⚠️ 早先写错的一处（已改回）**：我一度把 **B（固件在环）移出主线**，理由是它最贵、
且仿真≠真机。**那是把"成本排序"当成了"要不要做"** —— 两件事：
**ABC 是能力面，三条都要做出来**（用户 2026-10-14 明确指出：「ABC 都是主线都要兼容做出来，
这展示了功能多」）；**成本只决定先后，不决定取舍**。
⇒ B 恢复为**主线的一条（P5）**；"仿真≠真机"这条**保留为诚实标注**（结论需真机校准），
  但不再作为"不做它"的借口。

**没变的**：A/B/C 各自的**验证方法全部保留**（真跑、贴退出码与日志、接错脚就该什么都不发生）。

## 1. 顺序，以及为什么

**★ 先说清一件事：ABC 三条都是主线，都要做出来**（这是能力面 —— 功能多是优势）；**
下面的期次只决定先做哪个，不决定砍掉哪个。**

```
P0 加型号引脚定义（不需任何外部条件）
  ↓
P1 ESP32 · 服务端回读        ← 有板、有工程、有工具链 ⇒ 最快见效
P2 ESP32 · 串口回读
P3 ESP32 · 烧录
  ↓
P4 ★ 抽出通用「硬件适配器」接口   ← 真正的交付物
  ↓
P5 ★ 固件在环（Renode / QEMU）    ← 主线之一（原 B）；与真机线**并列**，不互相阻塞
  ↓
P6 STM32 验收（最后）            ← 只写适配器，看能不能不碰核心
```

**为什么 ESP32 先行**（2026-10-14 实测，逐项当场验证过）：

| 要件 | ESP32 | STM32 |
|---|---|---|
| 板子 | ✅ 用户手上有（智座用 DevKit V1 / `board = esp32dev`）| ❌ 没有 |
| 工程 | ✅ `D:\MAX_xiangmu`（**已经在插件里建模过**）| ❌ 没有 |
| 工具链 | ✅ PlatformIO Core 6.1.19 已装（不在 PATH）+ `pyserial` 已装 | ❌ `STM32_Programmer_CLI`/CubeMX/`arm-none-eabi-gcc`/`openocd`/`make` **全无**，常见安装目录也不存在 |

★ **还有一处天然对接**（这是 ESP32 能当第一块试金石的关键）：
智座固件 `main.cpp` 里 `IR_SENSOR_A_PIN = 23`（ir_front）、`IR_SENSOR_B_PIN = 27`（ir_back），
与插件建模的 **`E4` = GPIO23、`E19` = GPIO27 完全一致**
⇒ 场景里的接线与真板的接线**说的是同一件事**，真机在环才有可能"对得上"。

## 2. 当前能力边界（准确版，别记错）

```
hw_run_simulation → 起一个 **Python 进程** → 挂 I2C shim（smbus / RPi.GPIO）
                  → 虚拟时钟可加速
                  → ⚠️ RPi.GPIO.input/output **故意抛 NotImplementedError**（v1 只覆盖 I2C）
```

- 现在模拟的是「**宿主机上的 Python 程序**」，**不是 MCU 固件**。
- 全仓搜 `stm32|cube|CubeProgrammer|openocd|烧录|串口|esptool|platformio`：
  **命中全是文档引用**（引自智座自己的 `烧录与PIR接线操作指南.md`、`platformio.ini`），
  **没有一行是能力实现** ⇒ **现在完全不能驱动任何 MCU 工具链**。
- ✅ **装配层是通用的**：摆器件 / 连线 / 电压·方向·I2C 上拉校验 —— 对 ESP32、STM32 一样适用。
- ✅ 已有的"真链路"是：真 Python 程序 → 真 HTTP → 真服务端 → 真数据库（**只有硬件那段是虚拟的**）。
  ⇒ 准确说现在是「**软件在环 + 虚拟硬件**」。

## 4. P4 的交付物：适配器接口草案

```
detect()   → 工具链在不在、板子在不在（探测失败要**说清缺什么**，不是静默返回 false）
flash()    → 调 CLI：**退出码 + 完整日志可回看**（不是"点完就没"）
read()     → 读数来源：串口 / 服务端 二选一（同一份接口）
reset()    → 复位
pinMap     → 虚拟 portId ↔ 真板丝印（如 E4 ↔ GPIO23）
```

**三条不可妥协的纪律**（本项目失败族的直接教训）：

1. **失败要可见** —— 工具链失败不能只打印"完成"；
2. **`ok:true` ≠ 效果发生** —— 曾经 `models.get(k) !== undefined` 因 Promise 恒真而全军覆没；
3. **读数来源自实际接线** —— 沿用 `hw_set_occlusion` 的语义：**没接上、接错脚，就什么都不该发生**。

## 5. 边界（"通用"到底通用在哪 —— 免得验收时混淆）

**★ 通用的是「接口与流程」，不是「外设语义」。** 这两件事必须分开讲，
否则"所有硬件都能适配"会被听成"所有硬件开箱即用"，而后者做不到：

| 通用 ✅ | 不通用 ⚠️ |
|---|---|
| **适配接口**（探测 / 烧录 / 回读 / 复位 / 引脚映射）—— 定一次，所有板子共用 | **外设语义**：I2C/USART 已覆盖；**SPI / ADC / 定时器 / DMA 要逐个建模** |
| **装配层**：摆器件 / 连线 / 电压·方向·上拉校验 —— 对所有 MCU 一样 | **非 MCU 类硬件**（FPGA / 专用芯片 / 模组）语义差别更大，需各自适配器 |
| **流程**：型号定义 → 装配 → 校验 → 烧录 → 回读 → 在环验证 | **工具链差异**：PlatformIO / CubeCLT / esptool / openocd 各写各的适配器 |

⇒ 所以本插件做"通用"的现实路径是：**我们定接口 + 注册机制，生态往里填硬件**
（第三方可提供**适配器包**或**型号定义**）。**我们不可能自己适配所有硬件** ——
但可以让"加一块新板子"的代价降到 **L1（只加数据）或 L2（只加一个适配器）**。

2. **不替代 CubeMX / CubeIDE** —— 我们是**把它们串起来 + 让接线关系参与校验**。
3. **固件在环（P5）要做，但结论必须标注"需真机校准"** —— ⚠️ **仿真≠真机**
   （时序、中断优先级、寄存器副作用都有偏差）⇒ 它是**主线能力之一**（要做的就是它），
   但它的结论**不能单独当成"真机通过了"** —— 要用真板对照（P1–P3 正好提供了对照组）。
   ⇒ 这条是**诚实标注**，不是"不做它的借口"。
4. **真机是墙钟** —— 真机在环不能像虚拟时钟那样加速（与联网设备同一个坑，见 `docs/07`）。
5. 不预置别人的项目与模型；第三方模型仍不分发。
